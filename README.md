# freelance-hunter v2

**Универсальный агрегатор заказов и вакансий.** Собирает ленты с 11 площадок, отсеивает мусор
и «плохих» заказчиков по объективным метрикам, готовит отклики, ведёт учёт откликов и уведомляет в Telegram.

```
11 источников  →  единая модель Job  →  дедупликация  →  скоринг качества  →  база SQLite + UI + MCP
```

Хранилище — **SQLite** (встроенный `node:sqlite`, без внешних зависимостей): мгновенный поиск,
фильтры по индексам, безопасные параллельные записи.

```bash

```

### Настройка сессии

```bash
npm run login                       # alot.pro: логин руками → куки UID+S сохраняются

```

Импорт cookie-файлов поддерживает **5 форматов** (определяются автоматически):

1. Netscape `cookies.txt`
2. Chrome / EditThisCookie / Cookie-Editor JSON
3. Playwright `storageState.json`
4. JSON `{cookies:[…]}` или `{name,value,domain}`
5. сырая строка `name=value; name2=value2`

Сервис определяется по домену (fl.ru → flru, kwork.ru → kwork, hh.ru → hh).

## ИИ-подбор (новое)

ИИ читает твоё резюме, строит профиль и подбирает закаты, которые тебе подходят.
Если сомневаешься, какой заказ взять — спрашивай ИИ прямо по ленте.

### Провайдеры: любые ключи, любые провайдеры

- **Автоматически подтягиваются из конфига opencode** (`~/.config/opencode/opencode.json` и `D:/opencode/config/opencode.json`) — baseURL + ключ + список моделей. Ключи никуда не копируются, читаются на лету.
- **Свои провайдеры** — добавляешь в UI или CLI: любой OpenAI-совместимый эндпоинт (OpenAI, DeepSeek, GLM/Z.AI, Groq, OpenRouter, Moonshot, Together, Ollama, LM Studio, vLLM), Anthropic API или локальный Ollama.
- **Автофоллбэк**: если активный провайдер упал (rate-limit, нет баланса, 5xx) — автоматически берётся следующий рабочий. Недоступные провайдеры запоминаются на 2 минуты, чтобы не долбить их.

```bash
node bin/hunter.js ai providers             # список (35+ провайдеров из конфига)
node bin/hunter.js ai use oc:zai2 glm-4.5-flash
node bin/hunter.js ai add "мой OpenAI" https://api.example.com/v1 sk-xxx gpt-4o-mini
node bin/hunter.js ai test oc:zai2          # проверить связь
```

### Резюме → профиль

```bash
node bin/hunter.js ai resume "D:\Downloads\cv.pdf"
```

Поддерживаются **PDF, DOCX, TXT, HTML** — парсер свой, без зависимостей (для PDF свой разбор
потоков и ToUnicode-карт). ИИ вытаскивает: навыки, стек, опыт, категории, ставку, минимальный
бюджет, что готов освоить и что точно не хочет.

Профиль можно править руками — ИИ подстраивается под правки.

### Подбор и советы

```bash
node bin/hunter.js ai match --limit 40      # score 0-100 + вердикт take/consider/skip + причины + риск
node bin/hunter.js ai ask "какой заказ взять, если есть варианты с Тильдой и с 1С?"
node bin/hunter.js ai improve 17352142       # переписать отклик под профиль
```

Результат оценки сохраняется в заказы (`aiMatch`) и виден в ленте как бейдж «ИИ 85».

### В UI

Вкладка **«AI-подбор»**: провайдеры → резюме → профиль → подбор.
В карточке заказа: «Оценить заказ (ИИ)» и «Улучшить отклик (ИИ)».

| Инструмент | Что делает |
|---|---|
| `ai_status` | провайдер, модель, наличие профиля, сколько заказов оценено |
| `ai_list_providers` | список провайдеров (из opencode + свои) |
| `ai_set_provider` | выбрать провайдера и модель |
| `ai_test_provider` | проверить связь |
| `analyze_resume` | разобрать резюме (путь к файлу или текст) |
| `get_ai_profile` | текущий профиль |
| `ai_match` | оценить ленту по профилю |
| `ai_ask` | спросить ИИ по ленте |
| `ai_recommend` | топ заказов + что пропустить + риски |
| `ai_improve_response` | переписать отклик |

---


Каждый заказ получает **score 0–100** и вердикт:
`prime` (≥70) · `good` (≥55) · `meh` (≥38) · `bad` (<38) · `blocked` (стоп-слово).

Взвешенная модель (`src/core/quality.js`):

| Критерий | Вес | Источники сигналов |
|---|---|---|
| Клиент | 30 | рейтинг, число отзывов, опыт, % найма, верификация, возраст аккаунта |
| Содержание | 30 | совпадение с ключевыми словами, совпадение с навыками профиля, объём ТЗ |
| Цена | 20 | попадание в диапазон, адекватная ставка ₽/час (оценка по объёму текста) |
| Конкуренция | 10 | число откликов на заказ |
| Свежесть | 10 | возраст публикации |

Минус за мусор: стоп-слова (встроенные + свои), минус-слова, «срочно/дёшево/без опыта»,
CAPS-лок, эмодзи-спам, смешение кириллицы и латиницы, телефон в тексте, посты-резюме.

> Сопоставление слов — по основам, а не подстроке: «бот» ≠ «раз**бот**чик», но «дизайн» = «дизайнер».

Дедупликация (`src/core/dedupe.js`) склеивает один и тот же заказ с разных площадок
в группу и выбирает лучшего представителя (больше данных, адекватная цена, наличие метрик клиента).

## Лента и фильтры

В боковой панели: поиск по тексту, диапазон цены, минимальный score, «только избранное»,
«только новые», чипы вердиктов качества и **галочки источников**.

- Галочка источника = «показать этот источник». Снял все → пустая лента (а не «всё подряд»).
- Кнопки **«все»** и **«снять все»** — быстрый выбор.
- Поиск понимает русский язык без учёта регистра и ранжирует по релевантности:
  сначала заголовок начинается с запроса, потом — целое слово в заголовке, потом — в тексте.
- Сортировка по умолчанию — по качеству (score), при активном поиске — по релевантности.

Фильтры работают одинаково в UI, CLI (`--source`, `--verdict`, `--q`, `--min`, `--max`, `--score`)
и MCP (`list_jobs`).

## Настройки

Полная схема — `src/core/settings.js`, редактируется из UI (вкладка «Настройки») или через CLI/MCP.

```bash
node bin/hunter.js settings                      # все настройки
node bin/hunter.js set search.priceMin=5000
node bin/hunter.js set quality.minClientReviews=10
node bin/hunter.js set quality.maxResponses=25
node bin/hunter.js set quality.minSalaryPerHour=1500
node bin/hunter.js set apply.dryRun=true
```

Группы: `search` (слова, цены, биржи), `quality` (пороги клиента и цены),
`poll` (интервал, лимиты), `notify` (Telegram-бот), `apply` (автоотклик), `profile` (исполнитель), `ui`.

Профиль исполнителя влияет и на подбор заказов (совпадение по навыкам), и на текст отклика.

## Web-интерфейс

`http://localhost:3410` — пять вкладок:

- **Лента** — все источники сразу, фильтры (поиск, цена, вердикт, источник, score), карточка с разбором качества
- **Канбан** — new → drafted → sent → applied → done
- **Аккаунты** — статус всех площадок, импорт кук, telegram-каналы
- **Настройки** — профиль, поиск, качество, автоотклик, уведомления
- **Статистика** — счётчики, распределение по источникам, состояние опроса

API: `/api/jobs`, `/api/jobs/:id`, `/api/settings`, `/api/profile`, `/api/accounts`,
`/api/accounts/import`, `/api/accounts/check`, `/api/sources`, `/api/stats`, `/api/poll`,
`/api/apply/auto`, `/api/notify/check`, `/api/tg/channels`.

## Автоотклик

По умолчанию — **безопасный режим (dry run)**: тексты готовятся и сохраняются, но не отправляются.

```bash
node bin/hunter.js auto-apply --dry --score 70 --limit 5
node bin/hunter.js auto-apply --services flru,kwork --score 80   # реальная отправка
```

Используется Playwright с постоянным профилем в `data/profiles/<service>/` и куками из `data/accounts.json`.
При ошибке сохраняется скриншот в `output/apply-logs/`.

## Хранилище

`data/store.db` — SQLite (WAL-режим). Таблицы: `jobs`, `settings`, `meta`, `applied_log`, `source_state`.

При первом запуске данные из старого `data/store.json` переносятся автоматически
(JSON остаётся рядом как `store.json.migrated`). Если база повреждена — приложение
отведёт её в `.broken-<время>` и создаст новую, ничего не падая.

## Ответственное использование

Инструмент ходит на сайты бирж с умеренной частотой (пауза 1.2 с между запросами к одному хосту).

Встроена **защита от блокировок**: если хост отвечает ошибкой 3 раза подряд, он уходит на паузу
(1 мин → 5 мин → 15 мин), и состояние паузы сохраняется между запусками — приложение перестаёт
долбить сайт, который его заблокировал. Активные паузы видно в `hunter doctor` и в `/api/stats`.

Не меняйте паузу на 0 и не запускайте массовый опрос в несколько процессов: агрессивный опрос
может привести к блокировке вашего IP или аккаунта на стороне площадки.

## Ограничения

- Автоотклик работает в безопасном режиме (dry run) по умолчанию; реальная отправка
  на fl.ru/kwork требует импортированных cookie и проверенных селекторов формы.
- Данные о клиенте есть не у всех площадок: hh.ru даёт рейтинг и отзывы, fl.ru — возраст
  аккаунта и верификацию, kwork — число заказов и % найма. Пороги «минимум отзывов»
  применимы не везде.
- Парсеры зависят от вёрстки сайтов; при её изменении источник может начать отдавать 0 заказов
  (видно в состоянии источника).
- Сбор идёт по расписанию, пока открыт веб-интерфейс.
